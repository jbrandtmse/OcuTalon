## Intent

**Problem:** Lane B's step 4 contracts are not fixed yet: the spine does not name the webhook table, the hook application's header, cap and role, the email and MCP settings routes or `EmailIn`'s poll record; the five MCP verbs and `SendEmail` have no classes and no `CommandsIn` routes; `SettingsOps.RestartRunners()` (which Lane A's `McpOps` calls) does not exist; and nothing records which sessions belong to admins (ruling planner-2026-11-09-35.1 Q1), so Epics 21 and 22 cannot build in parallel.

**Approach:** Add Lane B's step 4 names to the spine as plain unions; add the six verb classes and their routes (MCP verbs `web_admin` only; `SendEmail` from `tool` only for the session user's own mailbox address, and from `system`); build `RestartRunners()` on the bridge's existing restart; record `AdminAtSignIn` on `Session` at each sign-in with the read API `Ownership.AdminSessions()`; stub `SettingsOps.SaveMcpEntry`/`RemoveMcpEntry` (ruling Q4, built in Story 21.4); propose the step 4 settings and request texts and ship only the accepted ones. The webhook build itself (the epics criteria 5 to 7) is proposed as sibling Story 35.3 (Design Notes, "Proposed split").
