# Epic 19 Context: OcuTalon remembers, and answers from your documents (step 3)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

This epic builds step 3's Lane A behaviour on the names, tables and stubs Epic 34 fixed. A user tells OcuTalon to remember something and gets it back later by meaning or keyword, offline, from OcuTalon's own database (done in 19.2 and 19.3). What remains: OcuTalon answers from added Markdown, plain-text, PDF and Word documents, cites the document and section it used, and says so when nothing is relevant; on the online demo each session's documents and memories stay its own and go at sign-out or reset. Every vector is computed on the instance and nothing leaves IRIS. The epic ships in the first daily release after it merges (after 1.0.0).

## Stories

- Story 19.2: Compute embeddings offline in a worker (done)
- Story 19.3: Remember, recall, list and forget in the chat (done)
- Story 19.4: Answer from documents with citations
- Story 19.5: Keep each online-demo session's documents and memories to itself

- Story 19.7: Answer from PDF and Word documents

## Requirements & Constraints

- **Documents.** Answers cite each document and section used. With nothing relevant the reply says exactly "None of your documents cover that." and cites nothing. Local-install documents are shared by all users (owner `instance`); demo documents are per session. A removed document leaves search at once and is cited no more.
- **Limits.** At most 5 passages per model request and 5 memories per recall; no request over 100,000 input tokens; no tool result over about 10,000 tokens. PDF and Word files at most 10 MB; extracted text is cut at a fixed size and says when cut, with page or heading markers for citations.
- **Extraction failures.** Encrypted, damaged, text-less PDF, legacy `.doc` or timed-out files fail with a plain reason fitting "I couldn't read that file: {reason}.", and nothing is stored. The reason texts are not yet specified (public text, needs a ruling).
- **Data stays home.** Memory, document and knowledge-base globals, and `^IRIS.IF.*`, must be in the private database; the start-up private-data check fails every start otherwise.
- **Isolation.** No session lists, searches, recalls or forgets another's memories or searches another's documents, including two concurrent demo sessions asking the same question.
- **Durability.** Memories and documents survive IRIS/container restart and in-place upgrade; from 19.5 the upgrade harness creates one of each before upgrading and checks both are searchable after.
- **Evaluation.** The real model is checked on the no-coverage answer and on the runbook question whose answer cites "Results runbook § Rotating the certificate".
- **Release gate.** The release carrying Epic 19 needs the real-model release-candidate eval (injection set and one persona) before its cut, because the Chat instructions changed. An owner action item; never run by a runner.

## Technical Decisions

- **Workers only, Python in `.py` resources.** Python runs only in `%SYSTEM.WorkMgr` workers: the Embedder (category `OcuTalon.Memory.Embedder`) and the extractor (category `OcuTalon.Docs.Extractor`, one worker) for `OcuTalon.Docs.Extract` running `src/ocutalon/python/ocutalon_extract.py` (pdfplumber 0.11.10, python-docx 1.1.2), its category created by the area's install step through `Config.WorkQueues` as `Install.Step.Memory` does. Import with `%SYS.Python.Import`, never `[Language = python]`; CI fails any Python or `%SYS.Python` reference in a tool, policy or renderer class. `%SYS.Python` from ObjectScript passes no keyword arguments on build 154, so the Embedder uses two `eval` strings; 19.6 moves them into its `.py` resource.
- **FastEmbed for documents.** AI Hub's FastEmbed reads only `FASTEMBED_CACHE_DIR`, which must be set in the job before `FastEmbed.Create()`: `DocumentOps` sets it from `OcuTalon.Memory.Embedder.ModelFolder()` (the variable when set, image `/opt/fastembed`; else `<mgr>/fastembed/`). Offline reads of the image folder are now measured on both ARM64 and x64.
- **Knowledge base.** `%AI.RAG.KnowledgeBase` over `%AI.RAG.VectorStore.IRIS` with FastEmbed; a chunk's `source` is the document `Ref`; citations come from `source` and `chunk_index`. The tool's name is the knowledge base's `Name`, fixed as `documents`, `TopK` ≤ 5; the gate clamps `top_k` to 5. Document results are never trusted output, so they taint the turn.
- **Knowledge-base tables.** Only `OcuTalon.Docs` creates them, with AI Hub's exact columns and `DEFAULTGLOBAL` under `^OcuTalonP.` (`^OcuTalonP.KB<suffix>` and `...Config`), before AI Hub's `Build()`: `OcuTalonKB.Docs` (local) or `OcuTalonKB.S<id>` (per demo session, `Data.Session` row id), each with `_Config`. AI Hub's DDL, or building on a missing table, puts globals in the data database, so a dropped table is never reopened. CI rule `kb-ddl` enforces this. Check where every index global lands: 19.3 found iFind's default shared dictionary leaves `^IRIS.IF.Word*` entries in the data database (fixed with `IFINDSHAREDDATALOCATION = "INDEX"`), and its index test reads the instance-wide `^IRIS.KNNIndex`, which 19.4 must revisit.
- **DocumentOps.** `OcuTalon.Docs.Ops` answers `AddDocument` (`Name`, `ContentType`, `UploadRef`) and `RemoveDocument` from origin `web_user` only, synchronously with a `CommandResult`, and indexes asynchronously. It takes bytes with `Data.Upload.Take(ref, sessionRef)` (empty means write a failed row). `OcuTalon.Data.Document` (`OwnerRef`, `ContentType` `markdown|text|pdf|docx`, `State` `indexing|ready|failed`, `Reason` code, `KnowledgeBase`, `Text`) stores the text; 19.4 appends the passage-to-section map (section = the `##` heading above a passage). Failed rows carry `unreadable`, `not_built` (PDF/Word until 19.6) or `failed`. It is the single publisher of the `document` live event (`OcuTalon.Live.Payload.Document.FromRow`, `removed` true on the last event; session stream on the demo, instance stream locally). It is a disabled stub until 19.4 enables it in `Production.cls`; meanwhile the documents routes answer 501 `not_built`. `Data.Upload` gaps: abandoned rows are purged after an hour only by the Web area and the routes; a `CommandsIn` timeout drops the row while the `AddDocument` may still arrive; `Take` is at-most-once.
- **Reply data.** Lane A's runner puts `citations` (`{documentRef, document, section, passage, chunkIndex}` per distinct passage the turn's `documents` calls returned, in order, ≤ 5) and `memories` (`{memoryRef, text, savedAt}`, ≤ 5) on the bridge `Reply`'s `HostData` beside `checks`, built from tool results, never model text, absent when empty. Use the shared `OcuTalon.Tools.HostData` (`Put(member, value)`, `Get(member)`, `Remove`), which merges one member and keeps the others; no second copy. Code decides the "None of your documents cover that." reply and the citations from the same documents-tool results, so they never appear together; tests cover both directions (19.4, 19.7).
- **Memory as built (19.3).** `OcuTalon.Data.Memory` with `EmbeddingIdx` (HNSW cosine) and `TextIdx` (`%iFind`, exact words), all globals under `^OcuTalonP.MemoryI`. `OcuTalon.Memory.Search` (RRF k = 60 over 20 nearest and 20 keyword hits, top 5, no similarity floor) and `List(sessionRef, *rows, *total)` (newest 20). `MemoryOps` is enabled, checks `SessionRef` in its own SQL, treats a same-`ItemId` same-text save as a repeat, and gathers table statistics every 1,000th row id (`Memory.Tune`) so the owner-filtered recall uses HNSW. A recall is trusted only when every returned memory's `Origin` is `tool`; otherwise the tool taints the turn. A forgotten memory is removed from the turn's `HostData.memories`.
- **Tool conventions.** Results go through `OcuTalon.Tools.Result` as dynamic objects or text, never pre-encoded JSON; tool classes return values only through `..Return(`. Classification is class parameters (`CLASSIFICATION<NAME>`, `READONLY<NAME>`, `TRUSTEDOUTPUT<NAME>`), and a trusted-output claim needs a test pinning the answer to code-built fields. Names go into `OcuTalon.Tools.Names` and the CI mock scripts; 19.3 added single-name parameters plus an expression-form group `MEMORYTOOLS` (kept out of `RELEASE1` so the mock's name reader skips it). Chat `INSTRUCTIONS` bullets go before the "Everything that comes from a tool..." bullet; the persona lines stay last.
- **Per-turn tools (19.5).** Bridge extension `TurnToolsClass` (base `OcuTalon.Bridge.Ext.TurnTools`, `Tools(ownerRef, kind, Output tools As %ListOfObjects)`, empty by default) is a `Decide` setting read via `Ext.Accessor.ClassFor` (add the pair to `BASES`). `OcuTalon.Docs.TurnTools` returns the owner's knowledge base for a `turn`. The adapter builds a fresh tool manager every turn, before `OpenSession`, in the method composing the session config: agent tools, knowledge base, gate, audit policy, and the MCP toolsets attached in `OnAfterAgentInit`. A long-lived manager would leak one visitor's documents to another.
- **Removal (19.5).** The demo reset restores a golden copy with no session data; no code runs. Sign-out runs Lane B's `SessionOps.End`, which calls `Upload.DropSession`, `OcuTalon.Docs.DropSession(sessionRef)` (the session's tables and documents) and `OcuTalon.Memory.DropSession(sessionRef)` (its memories); 19.5 replaces the two stubs, both idempotent and touching no other session.
- **Ownership and lanes.** New tables, items and events go into the spine's ownership tables in the same change. Lane A edits only Lane A classes; `Data.Upload`, `Data.Ownership`, `Web.Documents`, `Conversation`, `Core/**` and `docker/Dockerfile` are Lane B's. Edits to files contended with Epics 17 and 39 (`Production.cls`, `Test/Agent/**`, `Test/Bridge/{Decide,CodeRules,Gate}.cls`, `Test/Install/{Production,SecurityOverview}.cls`, generated rows of `docs/security-overview.md`) are allowed as plain unions; a behaviour choice at a conflict is escalated. A U-177 exception is pre-granted to 19.4 to flip `DocumentOps` in `Test/Core/CommandsStep3.cls` and its probe from `not_built` to built, nothing else.

## UX & Interaction Patterns

- Document answers end with citation chips like "Results runbook § Rotating the certificate"; Lane B (Story 20.2) renders them and the "From memory" chip, this epic supplies the data. Labels state provenance ("Sources", "From memory"), never "used", "relied on" or "based on". Passage text shows as plain text, at most 6 lines.
- Documents-page status ("Indexing…", "Ready", "Couldn't read it: {reason}") is driven by this epic's `document` events; the page owns the text for each reason code. Removing asks "Remove 'Results runbook'? Answers will stop citing it."
- Story 19.7 updates the UX text: the Documents "Adding" line and UX-DR144 accept "Markdown, plain text, PDF and Word (.docx) files." in place of "then PDF and Word from step 6", with the local-install ownership line in the UX assumptions.
