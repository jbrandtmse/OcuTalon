## Intent

**Problem:** The only fix OcuTalon can offer is repair and resend, chosen by the diagnosis. A user cannot ask it to contain a failure (suspend an item), undo that (resume), or route an incident's failed messages to another item (reroute), and a judge on the online demo has no way to see any fix beyond the guide's repair.

**Approach:** Three new fix kinds, `suspend_item`, `resume_item` and `reroute`, asked for in the chat through a new command-backed tool `propose_fix`. `IncidentManager` asks `FixExecutor` for the kind's dry run (synchronously), raises one `fix` approval request with it and tells the sessions; after approval `FixExecutor` re-checks and runs the kind from the row only, switching namespace in its one method. The online demo offers the reroute (to a new review item, `OrdersForReview`) and declines the item kinds, because every visitor shares the Orders production.

## Boundaries & Constraints

**Always:**
- Every action waits for one approval with a dry run that changes nothing (AD-16); the executor reads kind, parameters and targets from the approved row only and checks the kind's `RESOURCES` for the service user before running (existing `Executor.Execute`/`Unchecked`).
- The chat tool only submits a command (`Tools/CommandCall` pattern, AD-1); `IncidentManager` raises the request itself; the tool is `safe`, not read-only, trusted output, so the gate denies it in an untrusted or tainted turn (`Bridge/Policy/Gate.cls:167`).
- The diagnosis offers `repair_resend` only: the guide's incident stays on repair and resend (demo path first).
- Exactly one namespace-switching method in `Fix.Executor` (AD-3): `Resend` is widened, not copied.
- Producers never render (AD-32): every new user-facing server text is a catalog key in `Msg/Catalog/Watch.cls`, appended in one block.
- A result text claims only what happened: an item kind reports items changed, never messages resent.
- Copies and suspends OcuTalon made are attributed to their fix: a copy's failure joins no incident (`FixRun.CopyOf`), and an item OcuTalon suspended raises no "item disabled" finding.
- On the online demo (`Data.Public.Settings` `onlineDemo` = 1) `suspend_item` and `resume_item` refuse every item with a plain reason; `reroute` is offered.

**Never:**
- No new `/api/v1` route, no new table, no new live-event type, no grant to the user, demo, trace or public roles, no `%Ens_ProductionConfig` or `%Ens_ProductionRun` (`Install/Step/Roles.cls:13` forbids them).
- No suspend or resume of an item of OcuTalon's own production, and no reroute to a business service.
- No change to the guide's five steps or its incident (repair and resend), no automatic resume, no retry of a copy that failed again.
- No dependency on Stories 23.3, 23.4, 23.5, 23.7, 23.8 or Epic 36; no edit of 23.6's spec; nothing under `irislib/` or `irissys/`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Reroute asked | session's `open` (rejected) Orders incident, 50 orders failed at `OrdersFromPartner`; `propose_fix` `{kind: reroute, item: OrdersForReview}` | dry run `{affected 50, resend 50, leftOut 0, itemNoun, from OrdersFromPartner, to OrdersForReview, example <first header id>}`; one `fix` request; incident `awaiting_approval`; one `approval` Notification `incident.rerouteRequest`; tool outcome `raised` | No error expected |
| Reroute approved | the request above approved | 50 copies via `ResendDuplicatedMessage(id, , OrdersForReview)`, registered on the FixRun; originals unchanged; all complete -> `result.rerouted`, incident `resolved`, one Action audit entry with target and `to` | No error expected |
| Rerouted copy fails | a copy ends in Error | counted failed again (`result.failedAgain`), never retried; its failure joins no incident | Reported, not retried |
| Reroute target invalid | target missing, disabled, the messages' own item, or a business service | tool outcome `refused` with the kind's reason; nothing raised | Plain reason |
| Suspend asked (local) | `onlineDemo` 0, resolved incident; `{kind: suspend_item, item: OrdersToWarehouse}` | dry run `{item, before enabled, after disabled}`; request raised; `incident.suspendRequest` | No error expected |
| Suspend approved | approved, item still enabled | `Ens.Director.EnableConfigItem("<production>\|\|<item>", 0)` in the production's namespace from `Executor.InProduction`; FixResult Total 1, Completed 1, Resent 0; `result.itemSuspended`; incident `resolved`; no `watch.itemDisabled` finding | No error expected |
| Item changed since dry run | item already disabled at re-check | skipped with reason; `result.itemSkipped`; nothing changed | Plain reason |
| Undo | completed suspend; ask `resume_item` same item twice | exactly one resume request (second ask `already_asked`) | No second request |
| Online demo item kind | `onlineDemo` 1; `suspend_item` or `resume_item` | outcome `refused`, reason `ONLINESHARED`; no request, nothing changed | Plain reason |
| Own production | item of `OcuTalon.Production` | refused (`OWNPRODUCTION`) | Plain reason |
| Rejected / expired | a request of these kinds rejected or expired | nothing runs; `answered.rejected`/`answered.expired` to each recipient; incident `open` with that variant | Existing path |
| No approved row | `Execute` for a pending, rejected, unknown or non-fix Ref | nothing written, sent or changed; one Type 4 line | Existing refusal |
| Missing resource | service user lacks `%Ens_ConfigItemRun:U` | run could not start: kind's `NOTALLOWED`; `result.itemNotChanged` | Plain reason |
| Untrusted turn | an injected email (or a tainted turn) leads the model to `propose_fix` | gate denies `UNTRUSTED`; no command, no request | Denied |
| Diagnosis names a new kind | diagnosis payload `fixKind` `reroute` | payload check fails (only diagnosis kinds); existing refused/fallback route | Existing route |
| DW-823 | repair dry run refused by the good-message check (`GOODCHANGED`) | no-fix notice with key `incident.goodChanged` (not `incident.noFix`), variant `no_fix` | No error expected |
