# Epic 1 Context: Every item gets an attention decision you can audit and afford

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Build the bridge's decision core (Lane A) on Epic 0's merged contracts and stubs: three declarative AI Hub agents on Claude Haiku 5.5, one agent-runner operation per agent on AI Hub's own adapter, and the `Decide` process. Every item gets exactly one recorded attention decision with outcome, reasons, confidence, four token counts and cost; every model request and tool call is an agent step in Visual Trace; an unusable reply takes a fixed fallback route that never acts; conversations survive restarts; and OcuTalon starts safely with no model key. Every later epic (approvals, watch, fixes, the chat page, evaluation) calls models only through this pipeline, and the separable bridge must also run alone, in a production with none of OcuTalon's channels or web app.

## Stories

- Story 1.1: Every agent runs on Claude Haiku 5.5 through the Config Store
- Story 1.2: Agent runners send every request under the model rules
- Story 1.3: Decide records exactly one attention decision per item
- Story 1.4: Every turn and decision carries its tokens and cost
- Story 1.5: Every model request and tool call is an agent step in Visual Trace
- Story 1.6: An unusable reply takes the fallback route, and OcuTalon starts with no key
- Story 1.7: Timeouts and rate limits end every decision on time
- Story 1.8: Conversations survive restarts
- Story 1.9: No model request goes over 100,000 tokens (size check, `too_large` and the tool-result cap; compaction moved to Story 30.1)
- Story 1.10: The chat agent sets, lists and cancels reminders

## Requirements & Constraints

- **Model rules.** With only `ANTHROPIC_API_KEY` in `.env`, every agent uses `claude-haiku-5-5`. No request sets `temperature`, `top_p` or `top_k`. The output cap is 8,000 tokens, never below 4,000. Every test runs against the CI mock, which rejects sampling parameters and caps under 4,000. Every session carries the cache block, but the mock shows a cache marker only where the cached prefix reaches 512 tokens, so tests prove the block from the session config.
- **Keys.** A key comes only from the environment, through a placeholder resolved only inside AI Hub's provider. Its value never appears in a Config Store entry, a saved AI session, a production setting, the event log, an agent step, a log line or an error detail. With no key, every item runs, nothing in the production fails, and every decision falls back with `no_key`.
- **One decision per item**, unique on (item, kind); a repeat returns the recorded decision with no model call. Outcomes: ignore, digest, tell now, act. Confidence (0 to 1) is recorded but never changes the outcome. A user-written item answered ignore or digest becomes tell now, and the reasons say why.
- **Fallback.** An unusable reply is never an answer: it is recorded as tell now with the fallback flag and its reason, triggers no tool, fix or approval, and is flagged in Visual Trace. On a chat turn the fallback is a reply only; an item's fallback is a decision its caller notifies. CI forces every reason through mock scenarios.
- **On time.** Every decision and turn finishes, or falls back, within `Decide`'s timer (60 s default, never above 110 s).
- **Size and cost.** No request goes over 100,000 input tokens (one that would is never sent: `too_large`). All tool results of one model step pass at most 10,000 tokens together, and a cut result says so. Tokens and cost are recorded per turn and per decision, never per step. Each evaluation-set decision must cost under $0.001 on Haiku, measured from the usage rows.
- **Prompt safety.** The user's own text always reaches the model as a user-role message, never inside a tool result. Untrusted content is quoted data labelled with its source. Every request starts with a preamble stating the local time and zone.
- **No shell.** AI Hub's shell, filesystem, SQL and web-search tools are never registered; no tool runs operating-system commands, arbitrary ObjectScript or Python, or data-changing SQL. A test inspects every live ToolManager.
- **Durability.** AI sessions, conversation links and digest items survive restarts, in the private database on the durable volume. A read-only reviewer can follow any turn end to end in Visual Trace.

## Technical Decisions

- **The pipeline.** Caller → `OcuTalon.Bridge.Process.Decide` → runner → answer to the caller only; `Decide` sends nothing else except `OcuTalon.Bridge.Msg.AgentStep` messages to `AgentSteps`. Kinds: `decide` → `TriageAgent`, `diagnose` → `DiagnosisAgent`, `turn` → `ChatAgent`, `tool` (no model). `Decide` allocates the `DecisionRef`, prechecks, sends asynchronously under `SetTimer`, validates against the runner's `ReplyClass` (`OcuTalon.Bridge.Msg.DecisionPayload` for Triage), runs the `ReplyFilterClass` on model text before anything is recorded, records the `Decision` row with its `TraceSessionId`, and after commit fires HostSink `decision.recorded` with the `Ref` only (an `OnEvent` failure is logged, never fails `Decide`).
- **Runners.** All three items are `OcuTalon.Bridge.Operation.AgentRunner` on `OcuTalon.Bridge.Adapter.Agent` (subclass of `EnsLib.AI.Agent.OutboundAdapter`). Only runners call `Chat`; pool size is the concurrency cap. A runner refuses to start if `AuthPolicy`, `AuditPolicy`, `DiscoveryPolicy`, `IrisTools`, `AdditionalTools`, `IrisSkills`, `AdditionalSkills`, `SystemPrompt` or its own session-config setting is set, or its `AgentClass` isn't on the allow-list. It builds the agent on first use (so it starts with no key), always adds the gate and `OcuTalon.Bridge.Policy.StepAudit` in `OnAfterAgentInit`, sets `OcuTalon.Bridge.Context` before `Chat`, keeps `Response.Extra`, and copies `HostData` and the taint onto the `Reply`.
- **Callback rule (build 154 deadlocks or crashes otherwise).** Renderer, policy and tool classes make no `%AI` call beyond their base classes and run no Python; a test enforces it.
- **Agents and configuration.** `%AI.Agent` subclasses with static `XData INSTRUCTIONS`, `TOOLSETS`, `MODEL`, keeping Epic 0's `MOCKKEY` (`triage`, `diagnosis`, `chat`). No INSTRUCTIONS block contains `{{`; nothing calls `%AI.Utils.Template`. Triage has no tools, Diagnosis only `OcuTalon.Tools.Watch`, Chat the conversation toolsets. The model is the runner's `Model` setting, seeded only when absent; a Config Store entry's model is ignored, and the start fails if any runner resolves none. `ProviderConfig` is `@{config:OcuTalon<Agent>}`. `OcuTalon.Install.Step.Provider` is the only install-time writer of `AI.LLM.OcuTalon<Agent>`: `RebuildRegistry()` first, modify an existing entry rather than create, write before any runner setting naming it, and hold only provider, key placeholder, `base_url` and `http_config`. `x-ocutalon-mockkey` is added only when `OCUTALON_MOCK_KEY_HEADER=1`. At run time an entry changes only through the bridge's merge method (never writes a key), after which `SettingsOps` restarts the runners.
- **Session config** is built in code by one method from the agent and `OcuTalon.Bridge.Data.ModelFamily`, never stored, and passed as the same object on create and on every `OpenSession` (a resumed session without it loses cap and effort): `max_tokens` 8,000 (GPT-5-class: `extra_params.max_completion_tokens`), Anthropic effort in `extra_params.output_config.effort` from a runner setting (Triage `low`, Diagnosis `high`, Chat default), `max_iterations` 4 for Chat, the cache block `{"enabled":1,"cache_system_prompt":1,"cache_tool_definitions":1,"min_tokens_for_cache":512}`, and `timeout_ms`.
- **Timeouts.** `OcuTalon.Bridge.Timeouts.Derive(timer)` gives `timeout_ms` = timer − 5 s, `request_timeout_secs` = floor((timer − 10 s) / 2), and the full retry block `{"max_retries":1,"attempt_timeout_secs":<request timeout>,"initial_backoff_ms":500,"max_backoff_ms":2000}`, written whole into each entry's `http_config` (a partial block lets the back-off cap default to 30 s). Any timer change goes through `Derive` and restarts the runners.
- **Classification**, in one method and this order: precheck (`no_key`, `daily_cap`, `budget`, `too_large`; never sent) → `timeout` → `rate_limited`, `error` → `refusal`, `cut_off` (from `Response.Extra.finish_reason` `refusal`/`max_tokens`, Anthropic only), `empty`, `invalid`; anything indistinguishable is `unusable`. Every provider failure is `<%AICore>ProviderError`, classified by its text: "Rate limit exceeded" (429, 529) → `rate_limited`; "operation timed out" → `timeout`; the missing-key configuration error → `no_key`; "Invalid input" on a turn → `SessionBroken`; the max-iterations error → `unusable`; gateway 403 "daily cost cap reached" → `daily_cap`, never re-sent; else `error`. `rate_limited` is re-sent with back-off until the timer fires only when `ToolsRun` is false. A late reply is never passed on, but its usage row is still written.
- **Usage and cost.** After every `Chat`, even when `Decide` stopped waiting, the runner writes one `OcuTalon.Bridge.Data.Usage` row from the `GetStats()` delta around the call. Input tokens = prompt + cache-read + cache-creation; each tier priced from `OcuTalon.Bridge.Data.Price`, which `OcuTalon.Bridge.Installer` seeds (Haiku 5.5 $0.10/$0.50 per million; cache read 0.1×, cache write 1.25× input; 5× both above 100,000 input tokens; Sonnet 5.5 $2/$10). Decision and turn totals are sums of rows, carried as `InputTokens`, `OutputTokens`, `CacheReadTokens`, `CacheWriteTokens`, `CostUSD`, `Model`, `AgentStepCount`, `DurationMs`. `OcuTalon.Bridge.Budget.State()` returns spent, cap, capped and resets-at in UTC from `Decide`'s host settings `DailyCostCapUSD` (0 = off), `GatewaySpendUSD`, `GatewaySpendDate`; the day ends at instance-zone midnight via `OcuTalon.Bridge.Time`; owner `eval` never counts. `Budget.MarkCapped` marks the day once under a lock and fires `budget.capped` once (`ownerRef` `instance`, payload `{day}`).
- **Agent steps.** `OcuTalon.Bridge.Adapter.StepRenderer` (`OnBegin` returns "") records one step per `OnMessage`, with clock duration and an estimated request size from callback data only. `StepAudit` records each tool call through `%LogExecution`/`%LogDenial`. A step label is a class parameter of the tool class: `STEPLABEL<NAME>` for one tool of a multi-tool class, else `STEPLABEL`, else the generic "Running a tool"; never arguments or model text. Steps are buffered in the runner's job, passed through `OcuTalon.Bridge.Redact`, and emitted in order in the caller's trace session.
- **Conversations.** `OcuTalon.Bridge.Data.ConversationLink` maps (`OwnerRef`, agent) to an AI session; only the runner writes it, only for user `turn`s; every other request uses a throwaway, never-linked session. The runner holds `LOCK ^OcuTalonBP.Conv(<link>)` from `OpenSession` to `%Save`. **Saved conversations:** the runner saves a linked session only after a `Chat` that completed and whose context is not tainted, late or not; a tainted turn is never saved, so an untrusted tool result never reaches stored history and the next turn starts from the last untainted state. Busy: after a 2-second lock wait, `Decide` answers `Reply.Busy` = 1 (no text, no `Decision` row, not an error, not a fallback); fresh-session untrusted turns are exempt. `SessionMode` `fresh` with `SeedText` rotates the link to a seeded session, sends any `SystemNote` as code-written text before the input, and sets `SessionRotated`. A rejected stored history sets `SessionBroken` and is never repaired in place.
- **Tools** return a dynamic object or plain text through `OcuTalon.Tools.Result` (never pre-encoded JSON), which cuts against the step's running total kept in the bridge context and reset at each `OnMessage`. A tool takes no session argument (the `SessionRef` comes from the bridge context), declares its classification and step label as class parameters, and changes state only through `OcuTalon.Core.Commands.Submit` (origin `tool`, `IdempotencyKey` = the turn's `ItemId` plus the call's position), never writing domain tables.
- **Input.** `OcuTalon.Agent.Input` is the one renderer of an Item into the model's user message.
- **Digest store.** `DigestStore` (`OcuTalon.Digest.Store`, a real item) keeps digest items in `OcuTalon.Digest.Data.Item`, once per `ItemId`, read per session newest first; it notifies nobody, publishes no live event, and declares `Purge(daysToKeep)` (90 by default).
- **Bridge boundary.** `OcuTalon.Bridge` references no other OcuTalon package (CI check); it reaches its host only through `Decide`'s extension-class settings, read through `OcuTalon.Bridge.Ext.Accessor.ClassFor`. Bridge records carry `OwnerRef` (a `SessionRef`, `instance` or `eval`). Bridge globals are `^OcuTalonBP.<Short>`, registered in `src/short-names.tsv`, with committed, append-only `Storage` blocks. `src/bridge/` must load alone, run `OcuTalon.Bridge.Installer` and run `OcuTalon.BridgeExample` (the standalone-bridge job in `.github/workflows/lane-a.yml`).
- **Tests.** `%UnitTest` classes under `OcuTalon.Test.Agent`, `.Bridge` and `.Tools` (the `lane-a` shard). Lane A extends the mock only by adding scenario files under `ci/mock/scenarios/A/`, picked by a `[[mock:<name>]]` marker or the agent's `MOCKKEY`, with a per-test countdown for retry scenarios; new mock behaviour is asked of Lane B.

## UX & Interaction Patterns

- Chat speaks plain English in the first person: no greeting, exclamation mark, emoji or hype word, and no class name, error code or stack trace unless asked. Asked to run a command, it answers exactly "I can't run commands. I can check productions, read failed messages and propose fixes that wait for your approval." and calls no tool.
- Each bridge `FallbackReason` maps to exactly one of the UX catalog's 11 fallback reasons; `invalid`, `unusable` and replies from a provider with no stop reason map to the generic "the model's reply couldn't be used". The bridge never renders user-facing text; the catalog does.
- In Visual Trace, decision messages show `Outcome`, `Reasons`, `Confidence`, `Fallback` and `FallbackReason`, plus the turn totals, under plain names; a turn's steps sit in its thread beside its decision and reply.
