# Epic 11 Context: Release 1 ships: the demo path end to end, upgrade in place and a scripted release

## Goal

Epic 11 is release 1's merge point. The web demo path (no Telegram) passes end to end in the REL-2 Playwright test, the upgrade harness is built, and the clean-machine rehearsal installs a candidate and times one demo-path run against every bound. What remains in `release/`: the rehearsal's N repeats with Run again (so a real rehearsal can pass), a checklist, draft notes, and one scripted sequence (`release/release.sh`) that cuts a candidate, runs every gate, stops for the Contest Planner's hands-on pass and asks for the author's word before every outward step. Everything is proved only on throwaways. The first release is 1.0.0 (no previous tag, so its notes cover every merged story); Epic 38 runs the real cut through this sequence.

## Requirements & Constraints

- **Dry runs only in this build.** Throwaway hosts and repositories, the CI mock, never a real key; a met bound on the mock reads `dry run`, never `pass`. Every command fits one 10-minute call. Tests never write the real `release/records/` (always `--record <tmp>`). `release.sh` runs only in throwaway repositories with local bare remotes, never against GitHub. The repository is public.
- **Repeats (11.12).** N runs on one install (20 for real) with Run again and the replay rule between runs; every 11.11 bound over the whole set plus tell-now 5 s in 19 of 20 (floor(N/20) misses); a miss names run, step and bound; a planted miss in a later run fails the dry run. Known facts: Run again reopens only guide steps 3 to 5, so each repeat must send steps 1 and 2 through the composer; the replay rule needs the previous incident resolved and refuses a press within 180 s of an unnoticed run; REL-2 assertions are first-run counts, so repeats need relative counts (a new spec folder or an env-gated mode); a tell-now item must be added to each run (if the real model cannot be relied on to decide tell now, that is 11.12's tripwire). DW-522: specs 07 and 08 run once per install; 11.12 decides which specs repeat. DW-534: the collector's queries and page probes run only in the manual dry run; give them a check where a change would show, within the CI budget, or ledger why not.
- **Checklist (11.4).** Automated: the not-affiliated note "OcuTalon is inspired by OpenClaw and is not affiliated with or endorsed by the OpenClaw Foundation." word for word in README and About; no product name holds that name; licence notices kept; public-text check on the tree and the draft notes; no IRIS reference source tracked; no script publishes, changes repo settings or posts. Author rows `no-copied-code`, `no-artwork`, `no-ai-hub-copy`, `public-review`, `public-links` (DW-359), supplied by the Contest Planner as `- <id>: confirmed <date> <text>` lines; the script never writes them, and no text may read as if the pre-public review were missing.
- **Notes (11.13).** Plain language, grouped by area, claiming only what ships; class names and error codes only in a developer section; eval summary, rehearsal timings (bound rows and `### Runs` table), upgrade result, any REL-5 override reason. Never committed or pushed.
- **Release sequence.** First release refuses any version but 1.0.0 and any tagged version. Candidate `release/<v>-rc<n>` never changes after the cut; a failed gate means an integration-branch fix and `rc<n+1>`. Gates (11.14): full CI, release-candidate eval with the demo gate, upgrade harness, rehearsal, checklist, hands-on pass; only REL-5's override; refuse an enabled item answering "not implemented". The author's word before every outward step; never publishes notes or to a registry. Hands-on time at most 15 minutes (over: `WARN`). Record at `release/records/<v>/rc<n>.md` on the integration branch.
- **Secrets.** Never print an env or config value (no `env`, `printenv`, `set -x`, `declare -p`; `docker compose config --quiet`, `docker inspect --format` only); never `docker push|login|save|export`; records name machines only by OS, CPU and memory, no local absolute path; scan failures print `file:line`, never the text.

## Technical Decisions

- **Version (AD-23).** `src/module.xml` holds it; the cut stamps only the candidate's copy, builds the web bundle with Node.js, force-adds `src/ocutalon/csp/` and checks `/opt/ocutalon/version` in the built image.
- **Shared library.** `release/lib-release.sh` has `release_config_read` (`REHEARSAL_`/`DEMO_` keys outside the repo), `host_run <clean|driver>` (SSH with `StrictHostKeyChecking=yes`), `record_path`, `record_write <file> <section>` (replaces only its own `## ` section); 11.4/11.13/11.5 add `notes_path`, `release_previous_tag`, `candidate_branch`, `release_tags`, `next_rc`. New helpers go here, never copied. Scripts: Bash 3.2, ASCII, mode 100755, `umask 077`, main guard; `PASS|FAIL <id> <detail>`, then `RECORD` and `RESULT`.
- **Rehearsal (built).** `release/rehearse.sh` phases `plan|install|runs|exec|report|down|run`, options `--runs`, `--plant <bound>` (dry only), `--dry-run`; exits 0 real pass only, 1 fail/not run, 2 refusal, 3 dry run, 75 lane lock busy. `runs` does one timed run per call and today refuses run 2 or later (11.12 lifts that, reusing the collector, the marks and `bounds_eval`, and fills the tell-now row, which keeps a real Result `not run`). Specs reach IRIS only through `rehearse.sh exec` (via `host_run clean`); the collector only reads and ends `CHK|done|1`; it takes the first record at or after the run's server start. Page marks come from `web/e2e/support/rehearsal.ts`, inert unless `OCUTALON_E2E_MARKS` is set. One clock per value (server headers or page `Date.now()`, never mixed); a missing mark fails the run. Real mode needs a local driver, the candidate's own spec tree and `--runs` at least 20. Section `## Clean-machine rehearsal`; `test-rehearsal.sh` already takes about 36 s of the hosted checks job.
- **Checklist / notes CLIs.** `checklist.sh --version --rc [--candidate] [--record] [--notes]` (`fail`/`not confirmed`/`pass`; `## Release checklist`, reads `## Author confirmations`). `notes.sh --version --rc [--candidate] [--record] [--eval] [--notes] [--areas] [--replace]` (0 draft, 1 fail, 2 refusal, 3 dry run; prints `NOTES <file>`).
- **release.sh (11.5).** `start --version <v> [--from release/<v>-rc<m> --pick <sha>...] [--integration ...] [--remote origin] [--record]`; `next|resume|status`; one step per call, state under `${OCUTALON_RELEASE_STATE:-$XDG_STATE_HOME/ocutalon/release}/<v>-rc<n>/`; clock seam `OCUTALON_RELEASE_NOW`. Ordered `STEPS` of `step_<name>` functions that siblings insert into (11.14's gates before `notes`, checklist after). Exits 0 done, 1 failed, 2 refused, 4 stopped for the author's word; `ASK <id> <question> [yes/no]` on stdin, only `yes` proceeds. Cut in a temporary clone; two fast-forward pushes, never `--force`, tags or `main`. Section `## Release sequence` (`Mode:`, `Candidate:`, `Cut from:`, `Hands-on time:`, step table). The rehearsal gate calls `run --version <v> --rc <n>` and accepts exit 0 with `Result: pass` only.
- **Gates and outward steps.** 11.14 appends only `"release/*"` to the push branches of `ci.yml`, `lane-a.yml` and `test-ci-config.sh`'s pin (one line each, a footprint extension); the eval runs real only on the author's machine. 11.15's `## Hands-on pass` carries over only when `Cut from:` names the passed candidate plus the recorded fixes; a rehearsal never carries a pass. 11.16 reads `main`'s branch protection (12 required checks, the iris matrix expanded to `iris (<group>)`), refuses unless the ci.yml and lane-a.yml checks are required, then merges back into the integration branch; DW-27 routes here. 11.17 records the IPM artifact's path, size and checksum for Story 15.3. 11.18's hook copies a `git bundle` over SSH, runs `ocutalon-demo update`/`status` against a throwaway stand-in; rehearsal candidates are `rehearsal/<v>-rc<n>` on a local bare remote only, `Mode: rehearsal`.
- **Lanes (AD-29).** `release/` is Lane A's. Do not edit `README.md`, `docker/tests/lib-live.sh` (source only), `docker/Dockerfile`, `.gitignore`, `release/standalone-bridge.sh`, `release/ipm*`, `src/module.xml`, `web/e2e/demo-path/telegram-page.spec.ts`, or `.github/workflows/*` (except 11.14's line). Self-tests are hermetic `docker/tests/test-*.sh`; `ci/units.sh` changes only by plain union append.
