# Epic 11 Context: Release 1 ships: the demo path end to end, upgrade in place and a scripted release

## Goal

Epic 11 is release 1's merge point. The web demo path (no Telegram) already passes end to end in the REL-2 Playwright test, and the upgrade-in-place harness (`release/upgrade-harness.sh`) is built. What remains is the rest of the release machinery in `release/`: a clean-machine rehearsal (install, then timed demo-path runs checked against every bound) proved only on throwaways, a release checklist, draft notes, and one scripted sequence (`release/release.sh`) that cuts a candidate, runs every gate, stops for the Contest Planner's hands-on pass and asks for the author's word before every outward step. The first release is 1.0.0 (0.1.0 and 0.1.1 are never cut; no previous tag, so its notes cover every merged story). Epic 38 runs the real 1.0.0 cut through this sequence.

## Requirements & Constraints

- **Dry runs only in this build.** Throwaway hosts, repositories and the CI mock, never a real key; reports say "dry run", never pass. Every command fits one 10-minute call. Tests never write the real `release/records/` (always `--record <tmp>`). `release/release.sh` runs only in throwaway repositories with local bare remotes (may be named `origin`), never in a real checkout or against GitHub. The repository has been public since 2026-10-31.
- **Rehearsal bounds (11.11, 11.12).** Break the feed to notice: pick-up 15 s, settle end 30 s, diagnosis 20 s, delivery 5 s (every run); notice 60 s, step 1 decision 10 s, approval result 2 s, tell-now 5 s each in 19 of 20 (floor(N/20) misses); each reminder within 10 s; largest request under 100,000 input tokens; median, first reply and reminder-vs-result recorded. A miss names run, step and bound. 11.12 reruns N times on one install via Run again (DW-522).
- **Checklist (11.4).** Automated: the not-affiliated note "OcuTalon is inspired by OpenClaw and is not affiliated with or endorsed by the OpenClaw Foundation." word for word in README and About; no product name holds that name; licence notices kept; public-text check on the tree and the draft notes; no IRIS reference source tracked; no script publishes, changes repo settings or posts (no `gh release`, `gh repo edit`, `--visibility`). Author rows: `no-copied-code`, `no-artwork`, `no-ai-hub-copy`, `public-review`, `public-links` (DW-359). The CON-5 pre-public review was done by the Contest Planner (audit of all origin heads, 2026-10-30/31, log outside the repo); the Planner supplies the five `- <id>: confirmed <date> <text>` lines per candidate under delegation. The script never writes them; no text may read as if the review were missing.
- **Notes (11.13).** Plain language, grouped by area, from stories merged since the previous tag, claiming only what ships; class names and error codes only in a developer section. Include the eval summary, rehearsal timings, upgrade result and any REL-5 override reason. Never committed or pushed; the author edits and publishes.
- **Release sequence.** First release refuses any version but 1.0.0 (kit confirmed by the author) and any tagged version. Candidate `release/<v>-rc<n>` is never changed after the cut; a failed gate means an integration-branch fix and `rc<n+1>` (from the head, or from the passed rc plus cherry-picked fixes to carry a pass over). Gates (11.14): full CI, release-candidate eval with the demo gate, upgrade harness, rehearsal, checklist, hands-on pass; REL-5's override is the only one accepted; refuse an enabled item answering "not implemented". The author's word before every outward step (candidate push, record push, PR, merge, tag, merge back, demo update); never publishes notes or to a registry. Hands-on time at most 15 minutes (over it: `WARN`, no refusal). Record at `release/records/<v>/rc<n>.md` on the integration branch.
- **Secrets.** Never print an env or config value (no `env`, `printenv`, `set -x`, `declare -p`; `docker compose config --quiet`, `docker inspect --format` only); never `docker push|login|save|export`; records name no local absolute path and machines only by OS, CPU and memory. Scan failures print `file:line`, never the text.

## Technical Decisions

- **Storage append-only (AD-5).** Never rename, retype or remove a stored property; the storage diff runs against the highest earlier `v*` tag. `Reconcile` re-arms `ApprovalHold` and `ReminderTimer`.
- **Version (AD-23).** `src/module.xml` holds it; the cut stamps only the candidate's copy (`stamp_version`), builds the web bundle with Node.js (`ensure_web_bundle`), force-adds `src/ocutalon/csp/` and checks `/opt/ocutalon/version` inside the built image. Docker and IPM installs need no Node.js.
- **Shared library.** `release/lib-release.sh`: `release_config_read` (`REHEARSAL_`/`DEMO_` keys in `release.conf` outside the repo), `host_run <clean|driver>`, `record_path`, `record_write <file> <section>` (replaces only its own `## ` section), `notes_path` (`rc<n>-notes.md`), `release_previous_tag`; 11.5 adds `candidate_branch`, `release_tags`, `next_rc`. New helpers go here, never copied. Scripts: Bash 3.2, ASCII, mode 100755, `umask 077`, main guard; lines `PASS|FAIL <id> <detail>`, then `RECORD <file>` and `RESULT <result>`.
- **Rehearsal (11.3, 11.11).** `release/rehearse.sh` phases `plan|install|runs|report|down|run`; exits 0 real pass only, 1 fail, 2 refusal, 3 dry run, 75 lane lock busy; writes `## Clean-machine rehearsal`. A real pass needs 11.12.
- **Checklist (11.4).** `release/checklist.sh --version --rc [--candidate] [--record] [--notes]`; `fail` / `not confirmed` / `pass`, exit 0 only for `pass`; writes `## Release checklist`, reads `## Author confirmations`.
- **Notes (11.13).** `release/notes.sh --version --rc [--candidate] [--record] [--eval] [--notes] [--areas] [--replace]`; exit 0 draft, 1 fail, 2 refusal, 3 dry run; prints `NOTES <file>`.
- **release.sh (11.5).** `start --version <v> [--from release/<v>-rc<m> --pick <sha>...] [--integration feature/OCT_OcuTalon_MVP] [--remote origin] [--record]`; `next|resume|status [--version --rc]`; one step per call, state under `${OCUTALON_RELEASE_STATE:-$XDG_STATE_HOME/ocutalon/release}/<v>-rc<n>/`; clock seam `OCUTALON_RELEASE_NOW`. Ordered `STEPS` with `step_<name>` functions; siblings insert theirs (11.14's gates before `notes`, checklist after). Exits 0 done, 1 failed, 2 refused, 4 stopped for the author's word. ASK lines `ASK <id> <question> [yes/no]` read stdin; only `yes` proceeds; no pre-answer flag. Hands-on time is the sum of ASK windows. Cut in a temporary clone; the author's checkout only gets the record commit (explicit pathspec). Exactly two pushes, fast-forward, never `--force`, tags or `main`. Record section `## Release sequence` (`Result:`, `Mode: release`, `Candidate:`, `Cut from:`, `Hands-on time:`, `Run:`, step table); 11.5 ends `stopped after notes: no gate has run (not a release)`.
- **CI on candidates (11.14).** Append only `"release/*"` to the push branches of `ci.yml` and `lane-a.yml` and to `test-ci-config.sh`'s pin, one line each, reported as a footprint extension. The FR-57 `ipm-install` job lives on Epic 15. The eval runs real only on the author's machine (`--on-mock` is a dry run). The "not implemented" refusal can be static (enabled item whose class has `Parameter STUB = 1`).
- **Hands-on pass (11.15).** Defines a `## Hands-on pass` section (result, candidate SHA, findings with fix or deferral, carry-over note); carry-over valid only when `Cut from:` names the passed candidate plus only the recorded fixes; a rehearsal never carries a pass over.
- **Merging to `main` (11.16).** Branch protection on `main` is set (2026-11-01): 12 required checks (`checks`, `web`, `install-macos`, `iris (install-fresh)`, `iris (install-upgrade)`, `iris (production)`, `iris (browser)`, `iris (shards)`, `iris (shards-2)`, `iris (image)`, `standalone-bridge`, `evaluation`). The merge step reads it, expands the iris matrix into `iris (<group>)` names, refuses unless the ci.yml and lane-a.yml checks are required, and checks every job of the PR head's runs. Any job-name or matrix change goes to the orchestrator before merge. After merge and tag, `main` merges back into the integration branch. DW-27 (fork PRs) is routed here.
- **IPM artifact (11.17).** Bundle in `src/ocutalon/csp/` before packaging; the record names the artifact's path, size and checksum for Story 15.3. `src/module.xml`, `release/ipm-install.sh`, `release/ipm/*` are Epic 15's contended files.
- **Demo-host hook (AD-25, 11.18).** Over SSH (`DEMO_` config outside the repo): copy a `git bundle` of `v<v>`, run `ocutalon-demo update <v>` (`updated` / `scheduled` written into the notes), check `ocutalon-demo status`. No host configured: the notes say so. Tested against a new throwaway stand-in (no `ocutalon-demo` exists yet). U-203: rehearsal candidates are `rehearsal/<v>-rc<n>`, never `release/*`, never on origin; local bare remote only; rehearsal mode refuses a `release/*` name; `Mode: rehearsal`.
- **Lanes (AD-29).** `release/` and `release/records/` are Lane A's. Do not edit `README.md`, `docker/tests/test-readme.sh`, `docker/tests/lib-live.sh` (source only), `docker/Dockerfile`, `.gitignore`, `release/standalone-bridge.sh`, `release/ipm*`, `src/module.xml`, or `.github/workflows/*` (except 11.14's one line). `ci/units.sh`'s `CHECK_SCRIPTS` is a plain union append; self-tests are hermetic `docker/tests/test-*.sh`.
