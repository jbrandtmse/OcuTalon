## Intent

**Problem:** After Epic 0 the signed-in page is an empty shell: a header with only an "Account" menu over an empty `main`. It has no regions, no context badge, no theme menu, no About dialog and no shared controls for the later page stories to build on. A hash deep link is also lost at sign-in (DW-4).

**Approach:** Build release 1's page frame in the Angular app:
- the hash route, the landmarks and the headings;
- the full app header (badge, theme menu, account menu);
- the About dialog;
- the shared controls (button variants, a server button with a busy state, an inline notice, one polite announcer, a popover, a tooltip, and a dialog service over the Angular CDK).

`GET /api/v1/state` gains the few fields the frame reads. `signin.js` carries the URL fragment through sign-in. The sign-in page itself already meets its criterion (Story 0.3); this story confirms it and pins the two parts that no test covers yet.

## Boundaries & Constraints

**Always:**
- **Exact strings.** Fixed strings match the UX exactly. Non-ASCII characters are written as escapes in source (Rule 14); the strings below are all ASCII.
- **Styling.** Use only declared `DESIGN.md` tokens (`var(--x)` declared in `tokens.css`). The focus ring comes only from `base.css`'s `:focus-visible` rule, and no component overrides `outline`.
- **Signals and services.** Use standalone components with OnPush and signals. Use one typed `ApiClient`. The snapshot is loaded once per page load through one root `LiveState` service, and every consumer reads that service.
- **Sign-in page.** It keeps its `%CSP.Login` contract: action `Error:FullURL`, fields `IRISUsername`/`IRISPassword`/`IRISLogin` only. Its inline script stays ASCII with no `//` comments. `SignInAssets.cls` is regenerated by `npm --prefix web run tokens`, never edited by hand.
- **Browser storage.** Every read and write is wrapped so that a throwing or missing storage never breaks the page.
- **Server side.** Product values are read through `OcuTalon.Data.Setting.Get`, never a global. The snapshot's user comes from the session row (AD-4), never from the client.

**Never:**
- Never call `bypassSecurityTrust*`, `innerHTML` with server text, or an inline script in `index.html`.
- Never load a CDN, add a new npm dependency, or add a test runner besides Playwright and `node --test`.
- Never add a field to the sign-in form or a value to the Shell's 303 `Location`.
- Never call `OcuTalon.Install.Step.Demo.Mode()` from the web layer (it seeds a row).
- Never touch Lane A paths (`src/bridge/**`, `Install/**` except `Install/Step/Web.cls`, `docs/**`).
- Out of scope, each owned by a later story:
  - the snapshot's chat and rail contents, polling, the skeleton and its error UI, and Sign out through the API (2.2);
  - the rail's counts, rows and empty states (2.8);
  - the Visual Trace menu (2.9);
  - banners (2.10, 2.11);
  - skip links, the drawer, wide and narrow layouts, announcer batching, Firefox and WebKit (2.12);
  - the demo guide and the device regions (Epic 4);
  - the online-demo Sign out dialog and the countdown (Epic 16);
  - the About dialog's bridge-guide and security-overview links (31.3).
