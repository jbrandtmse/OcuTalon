## Intent

**Problem:** Step 3 has its names and Lane A stubs (Story 34.1) but none of Lane B's side: no memory or document command verbs, no documents REST routes, no `document` live payload, no Documents page, no sign-out drop of a session's documents and memories, and an image without `fastembed`, `pdfplumber`, `python-docx` or the baked embedding model. Epics 19 and 20 build on exactly these.

**Approach:** Add the four verbs and their `CommandsIn` routes; a forwarded documents dispatch class (`OcuTalon.Web.Documents`) that lists through Ownership, refuses a wrong type or an over-size PDF/Word file before any command, and submits `AddDocument`/`RemoveDocument` as `web_user`; the `document` payload and TYPES entry; a Documents page (header link, list, picker plus drop, remove dialog, live rows); `SessionOps.End` calling both `DropSession` stubs; and the Dockerfile lines. Lane A's stubs answer for now, so the tests run against them and against fixture rows.

## Boundaries & Constraints

**Always:**
- Names are 34.1's (spine AD-21 Names, cross-area row "Lane B contracts fixed by Story 34.2"): `OcuTalon.Msg.Command.SaveMemory` (`Text`, MAXLEN 2000; origin `tool` only), `.ForgetMemory` (`MemoryRef`; `tool` only), `.AddDocument` (`Name` MAXLEN 255, `ContentType` one of `markdown`, `text`, `pdf`, `docx`, `Content` `%Stream.GlobalBinary`; `web_user` only), `.RemoveDocument` (`DocumentRef`; `web_user` only); owners `MemoryOps`, `DocumentOps`. Inside a bridge context a `SaveMemory`/`ForgetMemory` whose `SessionRef` is not the context's `OwnerRef` is refused `not_allowed`, as `SendDigest` is (AD-1).
- No endpoint takes a `SessionRef` from the client; every read and the remove's target check go through `OcuTalon.Data.Ownership` (AD-4, AD-13). File content travels base64 in the JSON body (`{"name","content"}`); the route parses the body from the request stream, never through a string (a 10 MB PDF exceeds the longest string). 10 MB = 10,485,760 bytes.
- Page text is verbatim from EXPERIENCE.md or epics.md, non-ASCII written as `\u2026` and `\u00B7`; any other text is the lead's ruling (Design Notes, "Proposed"). ASCII only in every file; no local machine path anywhere.
- Contended files get only the edits in the Design Notes table, in the shape and place it names.
- The Dockerfile installs with one `pip install --target /usr/irissys/mgr/python --only-binary=:all:` line pinned `fastembed==0.9.0 pdfplumber==0.11.10 python-docx==1.1.2`, downloads the model at build into `/opt/fastembed` (root-owned, files 444, folders 555) named by `ENV FASTEMBED_CACHE_DIR`, keeps every package's licence files, and never pushes, saves, exports or caches any image.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| List | `GET /v1/documents`; online demo, fixture rows of sessions A and B | A gets `{"documents":[...]}` with only A's rows, newest `addedAt` first; local install: every user gets the `instance` rows | read failure 500 `server_error` |
| Add accepted | `POST /v1/documents` `{"name":"Results runbook.md","content":<base64>}` | one `AddDocument` (`markdown`, decoded bytes, the CSP session's `SessionRef`) through `Commands.Submit` as `web_user`; Ok: 200 `{"result":"done","ref"}` | `not_built` 501; other outcomes 500 |
| Wrong type | name not `.md`, `.markdown`, `.txt`, `.pdf`, `.docx` (any case) | 400 `{"error":{"code":"bad_document",...},"reason":"wrong_type"}`; nothing submitted | page row "Couldn't read it: {reason}" |
| Too large | `.pdf`/`.docx` of 10,485,761 bytes | 400 `bad_document`, `reason` `too_large`; 10,485,760 bytes is accepted | as above |
| Empty | 0 decoded bytes | 400 `bad_document`, `reason` `empty` | as above |
| Bad body | not an object with string `name` (1-255 chars) and string `content` | 400 `bad_document`, no `reason` | page shows the `failed` reason |
| Remove | `DELETE /v1/documents/:ref` | ref the session can't see: 404 first, nothing submitted; else `RemoveDocument` as `web_user`: 200 `{"result":"done"}`, `not_found` 404, `not_built` 501 | other 500 |
| Live row | `document` event `{ref,state:"ready"}`, then `{ref,removed:true}` | the row reads "Ready", then leaves the list, without reload | unknown fields ignored |
| Memory verbs | `SaveMemory`/`ForgetMemory` from `tool`; from `web_user`; in a context with another `SessionRef` | sent to `MemoryOps` (stub: `not_built`); `not_allowed`; `not_allowed`, nothing sent | |
| Document verbs from tool | `AddDocument`/`RemoveDocument` from `tool` | `not_allowed`, nothing sent | |
| Sign-out | `SessionOps.End` for a session | `OcuTalon.Docs.DropSession(ref)` and `OcuTalon.Memory.DropSession(ref)` called with that `SessionRef`; with the stubs, `ended` and the resume hash cleared | a failing drop: `failed`, hash kept, other steps still tried |

## Design Notes

**Governing ADs (Rule 6):** AD-1 (verbs, origins, `Submit`, `CommandsIn`), AD-4 (ownership API, sign-out drops), AD-12 (payload, TYPES, polling), AD-13 (REST, envelope, role check, the one unchecked prepare in `Ownership.Rows`), AD-19 (`onlineDemo` through `LocalFlag`), AD-21 (Names, event, refusals), AD-22 (throwaways), AD-23 (Dockerfile, pinned pip line, baked model), AD-29 (Lane B creates the step's verbs; lanes), AD-33 (one publisher: `DocumentOps`; the route publishes nothing). Conventions: REST, Live events, Angular (one API client), Times (`messageTime`), Tests, Stack. No AC contradicts an AD Rule.

**Decided in-stage:**
1. **Routes in a forwarded class.** `<Map Prefix="/v1/documents" Forward="OcuTalon.Web.Documents"/>` keeps every handler in a new file and leaves `Test.Web.Api.TestRoutes` (it counts `Route` elements only) and Epic 40's UrlMap hunk alone; `Web.Documents` extends `Web.Api`, so the role, admin and envelope checks run again in the forwarded dispatch. Fallback in Task 0 (a).
2. **Listing by `GET /v1/documents`, not `/state`.** Adding a snapshot key would edit `StateBody` and `Test.Web.Api`'s pinned key list (:132); the page loads the list on open and on a snapshot reload and overlays the store's `document` payloads by `ref`. A stale overlay lasts at most one poll (the newer event follows). Precedent: the settings page's own GET.
3. **Refusals at the route (DW-722).** The route refuses `wrong_type`, `too_large`, `empty` before any command and writes no row; the page shows that file's row from the 400 until it reloads (no Remove: nothing is stored). DocumentOps (Story 19.4) still checks and writes `failed` rows with `unreadable`, `not_built` (PDF and Word until Story 19.6) or `failed`. Codes live in `Web.Documents` parameters, the spine and `REASON_TEXTS`; not in `Msg.Enum` (not a listed Conventions enumeration, 34.1 left `Data.Document`'s values out, and Epic 40 rewrites Enum's end and `Test.Msg.Contracts`' exact parameter list).
4. **Content type by extension** (`.md`, `.markdown` -> `markdown`; `.txt` -> `text`; `.pdf`; `.docx`; any case); content is not sniffed (DocumentOps finds an unreadable file). Markdown and plain text have no size limit at the route (FR-54 caps PDF and Word; 34.1 review); veto if you want 10 MB for all.
5. **10 MB = 10,485,760 bytes;** `formatSize` rounds up: whole KB under 1 MB, one decimal MB from 1 MB.
6. **Valid adds before Story 19.4** reach a disabled `DocumentOps`, so the real route answers 500 (inference) and the page shows the `failed` reason; tests that need an accepted add use the route probe (unit) or `page.route` (browser), so no Lane B test changes when 19.4 lands. The AC's "its row appears as Indexing\u2026" is the page's own row while the add is in flight and the server's row afterwards (D9).
7. **Memory verbs get `SendDigest`'s context check** (governed default): a tool cannot save or forget for another session.
8. **Drops run first in `End`** (they replace `Set failed = 0`), so Epic 40's rewritten line is untouched; each step is still tried and the resume hash is cleared only when all succeeded.
9. **Model folder `/opt/fastembed`, outside `/opt/ocutalon`,** so the per-build `chmod` RUN never copies the 90 MB model into a new layer; the pip/model RUN sits before `COPY src/` so source changes reuse its cached layer. The download uses the `huggingface_hub` that `fastembed` installs (the same `models--Qdrant--all-MiniLM-L6-v2-onnx` layout as 34.1's evidence); the revision is recorded, not pinned (a pinned sha writes no `refs/main`, which AI Hub reads; inference).
10. **No visible drop hint and no column headers** (no unsourced text); the row is name, date, size and status side by side.
11. **Copies:** `SessionOpsDocuments` repeats `Test.Core.SessionOps`' ~20-line shadow-probe helpers, and `CommandsStep3` `SettingsCommands`' `NewCommand`; both siblings are contended with Epic 40. `Test.Web.DocumentsImage` has no sibling.
